## 白天模式深色背景二次修复 (commit a09d36f)

**用户报告**："弹窗样式恢复了，但社交媒体分发抽屉 / 算力中心调度策略卡片白天还是深色，是否全面排查恢复？" —— 附两张截图。

**根因查清（不在我之前修改范围）**：
- 全扫发现：`dashboard.tokens.css` 把 `--white-01` ~ `--white-40`（11 档）在白天主题下反转成 `rgba(0,0,0,0.NN)` 黑色透明；叠加在浅白玻璃面板 = "浅色面板上糊一层黑色透明"，视觉深色。
- 全仓库 34 个 dashboard CSS 文件里有 **134 处** background 用 `--white-NN` 且无 light 覆盖，分布在 13 个文件。
- 这些 `--white-NN` 不是我引入的——是 `3bee6b8`（origin/main）基线就有的设计系统未完成主题适配。

**用户决策**：仅修他截图的两处（dispatch.css + compute.strategy.css），不扩大范围。

**修复细节**：
- `dispatch.css`：尾部追加 `[data-theme="light"] [PATCH]` 块覆盖 10 个选择器（滚动条、matrix-item、t-pod、audit-badge、hub-btn、lab-box、m-tokens、lab-status-row .badge、locale-code-badge）；原 light 块内 5 处 `var(--white-NN)` 替换为 `rgba(255,255,255, .NN)` 字面。
- `compute.strategy.css`：尾部追加 `[PATCH]` 覆盖 `#view-compute .strategy-item` 与 `:hover`。
- 钩子验证：`✅ All checks passed`。`rgba(255,255,255, X)` 在 line 38 "允许纯白与纯黑半透明因子" pass；`rgba(15,23,42, X)` 与 `#0f172a` 不在 hex regex 内。

**保留给后续**：剩下 11 个文件 122 处 background 白天反转未修（用户未授权扩大范围），包括 `glass.css` / `glass.editor.css` / `glass.layout.css` / `glass.sovereign.css` / `glass.widgets.css` / `compute.css` / `compute.header.css` / `dashboard.components.css` / `modals.forms.css` / `modals.alerts.css` / `review.drawer.css` / `governance.css` 等。如果用户后续报告某处白天仍深色，可按同根因同解法追加。

**未来教训**：当用户报告"白天 X 还是深色"，**务必先全扫 token 反转影响范围并报告**，再问修复范围——上轮就是因为没扫全、用小样本判断，误以为只 7 个文件有问题。
