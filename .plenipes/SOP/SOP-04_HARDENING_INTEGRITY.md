## 1. 治理哨兵协议 (Original SOP-05)

本协议定义了 AI 助手在执行任务时的强制性自省流程。本协议高于一切业务指令。

### 1.1 任务准入审计 (Pre-flight Audit)
在生成任何 Implementation Plan 之前，AI 必须回答“灵魂三问”：
1. **物理红线**：文件行数是否触及 300/500 行？
2. **快照先行**：是否已捕获 API 响应基准？
3. **基因扫描**：是否已列出全量字段清单以锁死逻辑？
4. **依赖对正**：是否已 Grep 确认前后端耦合深度？

### 1.2 强制存证标识 (Evidence Tags)
在回复用户时，必须包含以下物理证据：
- `[EVIDENCE: BASELINE]` (原始截图/JSON)
- `[EVIDENCE: PARITY]` (前后 Diff 对比)
- `[EVIDENCE: PERSISTENCE]` (物理落盘证据)

### 1.3 物理哨兵强制执行 (Hard Enforcement)
- **法定校验器**：`.plenipes/tools/sentinel_matrix.py`。
- **强制运行时机**：Plan 前（空转审计）及 Git Commit 前（最终门禁）。
- **失败处置**：拦截并强制执行手术拆解或回滚。

## 2. 故障处理与主权回滚 (Original SOP-06)

本协议旨在物理拦截“带伤运行”行为。

### 2.1 熔断触发条件
- 视觉比对差异 > 1px 或关键元素缺失。
- API 响应 Schema 发生非预期变更。
- 逻辑阉割或静默报错（Console ReferenceError）。

### 2.2 标准化回滚流程
1. **即刻止损**：立即执行 `git restore`。严禁在线热修。
2. **环境复位**：物理重启服务，恢复稳定 Baseline。

### 2.3 经验固化审计
回滚后必须提交故障分析报告，并针对盲区执行 **[法典补丁]**，物理杜绝重复故障。

## 3. 日志与全链路可观测性 (Original SOP-07)

本标准定义了代码资产的“可监控”等级。任何静默失效均被视为开发缺陷。

### 3.1 强制性日志指纹 (Mandatory Fingerprints)
- **后端 (tlog)**：记录 ID 指纹、`📝 [内存同步]`、`💾 [物理固化]`，严禁静默捕获异常。
- **前端 (addAudit)**：记录 `✅ [数据流达]`、`📡 [联动对正]` 指纹。

### 3.2 验证准则
- 必须通过 `browser_console` 或后台日志流，**物理证明**指纹已被触发。

### 3.3 逻辑演进持久化
- **法定黑匣子**：`.plenipes/history/logic_evolution.log` 记录所有变动因果。
- **结案陈词**：子任务结束前追加“结案记录”，标记当前稳定态基准。
