# SOP-08: 跨对话接力与状态继承协议 (Cross-Chat Handover)

> [!IMPORTANT]
> **本协议旨在消除“对话衰老”导致的逻辑退化，允许通过开启新对话来“重启”AI 逻辑巅峰，同时保持任务物理状态的连续性。**

## 1. 退出快照 (Exit Snapshot) 触发条件
当满足以下任一条件时，当前会话的 AI 必须生成或更新 `.plenipes/SESSION_SNAPSHOT.md`：
- **手动挂起**：用户要求更换对话窗口或暂时停止任务。
- **上下文溢出**：AI 感知到对话过长导致理解能力下降。
- **手术中断**：在大规模重构（SOP-04）过程中需要跨越自然日或不同环境。

## 2. 快照内容规范
`SESSION_SNAPSHOT.md` 必须包含以下结构：
- **`Baseline_Hash`**: 任务开始时的 Git Commit Hash。
- **`Dirty_Hash`**: 当前工作区未提交变更的校验和（使用 `git diff | shasum` 生成）。
- **`Current_Task`**: 正在执行的子任务描述及 `task.md` 中的索引。
- **`Pending_Logic`**: 已经写了一半但尚未测试的功能，或存在于 AI 内存中但尚未落盘的意图。
- **`Next_Step`**: 接班 AI 应该执行的第一个动作。

## 3. 继承审计流程 (Inheritance Audit)
新对话开启后，接班 AI 必须：
1. **核实身份**：读取 `SESSION_SNAPSHOT.md` 并将其与物理 `git diff` 进行比对。
2. **声明主权**：如果比对一致，AI 必须向用户发送：“检测到合法的断点快照，我已继承上个会话的执行意志。”
3. **跳过预检**：使用 `pre_flight_check.py --resume` 绕过对脏工作区的拦截。

## 4. 异常处理
- 如果 `Dirty_Hash` 不匹配，说明物理文件已被篡改或丢失，接班 AI **必须拒绝执行**，并建议用户根据 SOP-06 执行回滚。
