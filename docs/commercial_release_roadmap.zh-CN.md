# Illacme Plenipes 商业发布路线图

## 1. 发布定位与决策

首个商业版本定位为 **本地优先（local-first）的专业出版工具**，服务需要自主掌控内容、模型凭据和发布渠道的创作者及机构。它的核心承诺是：用户的原稿、配置、索引、发布记录和凭据默认留在用户选择的本地存储中；产品不以托管或锁定客户内容为商业前提。

产品主路径：导入 Markdown 文稿 → AI 编辑与多语言加工 → 预览及人工审核 → 静态站点构建 → 发布至客户已授权的渠道 → 追踪发布结果并支持回滚。

这与 Obsidian 所代表的本地文件、用户选择和可携带性理念一致，但本产品聚焦于 AI 出版加工与分发，而非通用笔记管理。

首发前必须明确：

- 发行版本、定价单位（设备、席位或组织）和支持边界。
- 客户内容、生成内容与第三方渠道内容的所有权和责任边界。
- 本地许可证验证是否允许离线宽限期，以及设备更换的迁移规则。
- 仅使用由客户自行提供并授权的模型及发布平台凭据。
- 联网功能的目的、发送的数据、接收方和失败时的本地行为；用户必须能够逐项选择。

### 本地优先产品原则

1. **本地为真源**：Markdown 原稿与本地账本是系统权威来源；云端副本、缓存或发布产物不得成为恢复所必需的唯一来源。
2. **默认不上传**：除用户显式触发的模型调用、渠道发布、更新检查或可选同步外，不传输内容、凭据或行为数据。
3. **可离开**：停止订阅、撤销许可证或更换设备后，用户仍可读取和导出自己的原稿、配置、发布记录和审计数据。
4. **BYO 凭据**：模型与渠道凭据由用户保有；应用仅在本地加密保存，并支持随时移除。
5. **最小遥测**：遥测默认关闭；若用户选择开启，应匿名化、可查看、可删除，并与内容数据严格隔离。

## 2. 发布门槛

以下任一项目未完成时，不得对外收费或承诺生产可用性：

1. P0 问题关闭并获得独立复核。
2. 从空白环境完成安装、授权、一次发布与回滚的验收演练。
3. 发布制品可追溯、可复现，且依赖与安全扫描没有未接受的高危项。
4. 客户可获得许可证、使用文档、隐私说明、支持渠道及已知限制。
5. 至少三家设计合作客户完成真实但受控的端到端试用。
6. 在断网状态下可浏览、编辑、搜索、导出本地内容，并清楚标识需要联网的功能。

## 3. 阶段路线图

### 阶段 A：发布基础与风险清零（P0）

目标：让产品在法律、依赖与部署层面具备可交付的最低条件。

| 编号 | Issue 草案 | 交付物 | 验收标准 |
| --- | --- | --- | --- |
| COM-001 | 统一代码、文档和发行包的许可证 | 商业许可证策略、第三方声明、README 徽章及发行说明 | `LICENSE`、README 与安装包许可一致；律师或授权负责人确认对外销售权利 |
| COM-002 | 建立客户合同与数据条款 | EULA、隐私政策、DPA 模板、可接受使用政策 | 明确客户内容/AI 输出/渠道凭据权责、保留期限及删除流程 |
| COM-003 | 修复并锁定软件依赖 | 可安装 requirements 锁文件、SBOM、漏洞扫描流程 | 全新虚拟环境安装成功；无未豁免的高危漏洞；移除测试或恶意占位依赖 |
| COM-004 | 生产安全基线 | 威胁模型、认证/授权设计、密钥管理规范 | 不再使用全开放 CORS；高风险接口具备身份、权限和审计记录 |
| COM-005 | 改造生产 CI/CD | 受保护分支、发布制品、部署审批和回滚手册 | CI 不会直接修改或推送 main；部署配置无占位项目名；权限最小化 |
| COM-006 | 交付镜像加固 | 最小镜像、非 root 运行、镜像扫描与签名 | 容器可非 root 启动；扫描结果纳入发布门禁 |
| COM-007 | 落实本地优先与最小数据传输 | 数据流清单、离线模式、联网同意与本地加密方案 | 断网可完成本地创作与导出；每类外发数据均可追溯、关闭或明确说明 |

## 5. 首发验收场景

每次候选版本至少完成以下场景，并保留结果：

1. 新客户在隔离环境安装产品、创建管理员并完成许可证激活。
2. 导入包含图片、链接、多个语言的文稿，检查 AI 处理前后内容与来源可追溯性。
3. 配置一个测试发布渠道，执行预览、审批、发布、失败重试与回滚。
4. 更换设备并迁移许可证；撤销后确认专业功能按预期受限而客户内容仍可导出。
5. 模拟模型调用失败、渠道令牌失效、磁盘不足和进程中断，验证提示、审计和恢复路径。
6. 从备份恢复到新环境，并核对文稿索引、配置和发布记录。
7. 断开网络后，完成本地浏览、编辑、搜索、导出与恢复；尝试联网功能时应有明确、可理解的提示。
8. 查看网络活动与遥测设置，验证仅发生已获同意的模型调用、发布或可选同步。

## 6. 已知现状与追踪依据

- [已闭环] `LICENSE` 已切换为 **PolyForm Noncommercial License 1.0.0**，README / README.zh-CN / CONTRIBUTING 徽章与许可章节已统一，失效的 `file:///` 绝对路径链接已改为相对路径；商业授权入口见 `COMMERCIAL_LICENSE.md`（COM-001 完成）。
- `requirements.txt` 含格式异常的依赖声明与不应进入发行包的依赖，需由 COM-003 修复并纳入发布门禁。
- API 使用配置 Token 且当前中间件配置为开放 CORS，需由 COM-004 定义生产认证边界。
- 现有 CI 工作流具有直接写回 main 的行为，且部署配置存在占位值，需由 COM-005 替换为受控发布流程。
- 已有社区版/专业版功能矩阵；COM-101 负责把该技术矩阵转换为客户可理解且可执行的商业 SKU。

## 7. 不在首发范围内

- 多租户托管 SaaS、组织级 SSO/SCIM、复杂团队协作。
- 平台代管客户 AI 或分发渠道的生产凭据，以及默认上传客户文稿的云端工作流。
- 自动代投放、内容合规代审核和任何收益保证。
- 未经专项安全与合规评审的敏感行业部署。

## 8. 下一次评审

当 COM-001 至 COM-006 完成后，召开发布准备评审：逐项展示证据、确认遗留风险是否接受，并决定是否开始设计合作客户计划。未满足第 2 节门槛时，版本只能作为内部或受控试用版本分发。
